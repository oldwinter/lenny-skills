# Scoping & Cutting

使用来自 15 位产品领导者的框架，帮助用户有效 scope projects 并 cut features。

## 如何提供帮助

当用户请求 scoping 相关帮助时：

1. **理解 hypothesis** - 询问他们想学习或验证什么
2. **识别 appetite** - 判断他们愿意投入多少时间和资源
3. **找到 essential core** - 帮助他们识别 first version 必须包含什么
4. **为 learning 设计** - 确保 scope 能带来快速 feedback，而不只是快速 shipping

## 核心原则

### 使用 appetite，而不是 estimates
Ryan Singer: "We're going to go the other way around and we're going to say, what is the maximum amount of time we're willing to go before we actually finish something?" 设定固定 time budget（appetite），然后设计一个能装进这个约束里的 solution 版本。改变 scope，而不是改变 deadlines。

### MVP 是 validation tool
Eric Ries: "MVP is simply for whatever the hypothesis is that we're trying to test, what is the most efficient way to get the validation we need about whether a hypothesis is true or not?" MVP 不是 low-quality product，而是测试某个具体 hypothesis 的最高效方式。

### 把 list 砍半，再砍半
Eric Ries: "Write out the list of features that are necessary in your MVP. Cut it in half and cut it in half again and build that." Founders 总是高估什么才是 "minimum"。要到达真正 baseline，必须 aggressive cutting。

### Fixed time, small teams
Jason Fried: "Our appetite for any individual feature is no more than six weeks... So we have to figure out the simplest, most effective version of that to get that done within six weeks and get it done by two people." 约束会逼出 creative solutions。限制 team size 来保持 focus。

### Build the scooter, not the axle
Eeke de Milliano: "If you're trying to build the minimum viable product for a car, don't build just the wheels and the axle, build the scooter first." MVP 应该是较小 value proposition 的 functional、end-to-end version，而不是更大产品中的 incomplete piece。

### 使用 Wizard of Oz testing
Crystal W: "It's really this Wizard of Oz experience. We don't have to build anything. I coordinated with a bunch of interns and we were able to validate some of the value prop." 在投入 engineering 前，先手动验证 value propositions。用 humans 模拟 automated features。

### Kill 没按时完成的 projects
Jason Fried: "If there's any work that's left over that's still on the left side of the hill, meaning we're still pushing it up, we don't know how we're going to do it and we're at our time limit, it almost certainly dies." 如果 projects 没能在 allotted time 内完成，就让它们结束，避免 never-ending work。

### 把 pivot option 内置进 process
Paige Costello: "We added into our product process a notion that we might pivot or cut from stuff that we put on our roadmap because it felt like once it was on the roadmap, it had to be done." 把 cut 或 pivot roadmap items 的能力制度化，避免 sunk cost fallacy。

## 帮助用户的问题

- "你想用这个版本验证的 single hypothesis 是什么？"
- "在 ship something 前，你愿意投入的 maximum time 是多少？"
- "如果必须用一半时间 ship，你会 cut 什么？"
- "在 build automation 前，有没有办法手动 test？"
- "如果这个 feature 没按时 ship，你会 kill 它还是 extend？"
- "仍能交付完整 value 的最小东西是什么？"

## 需要提醒的常见错误

- **Estimating instead of time-boxing** - 问 "how long will this take?"，而不是 "what can we do in X weeks?"
- **Building the axle** - Shipping 更大 feature 的 incomplete parts，而不是 complete smaller features
- **Never killing projects** - 延长 deadlines，而不是 cut scope 或 cancel
- **Over-engineering the MVP** - 在测试 core hypothesis 前 build 太多
- **Ignoring the Wizard of Oz** - 即使 manual validation 更快，也总是默认 build

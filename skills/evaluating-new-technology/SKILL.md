# Evaluating New Technology

使用来自 22 位产品领导者的框架，帮助用户评估 emerging technologies；这些领导者曾在 Google、Shopify 等公司做过关键 technology decisions。

## 如何提供帮助

当用户请求 technology evaluation 相关帮助时：

1. **从问题开始** - 在讨论 tools 前，澄清他们要解决什么问题
2. **评估 maturity** - 判断这项 technology 对他们的 use case 是否足够稳定
3. **同时考虑 build 和 buy** - 帮助他们找到合适组合，而不是强行二选一
4. **为变化做规划** - 因为 landscape 会变化，所以要为 modularity 设计

## 核心原则

### Tools 解决问题，而不是反过来
Austin Hay: "I have this adage I always say, which is tools are just meant to solve problems. And the problem set for marketing technologists and business technologists is you focus on the tools." 选择 system 或 tool 前，永远先定义 problem 和涉及的人。

### Build AND buy，而不是 build vs buy
Austin Hay: "Build and buy as opposed to build versus buy. Build and buy means that both of you can win." 购买 tools 覆盖 90% 标准功能，再构建对业务独特的 "cool" 10%。

### 评估 mental bandwidth，而不只是 dollars
Dhanji R. Prasanna: "The savings and costs that there might be in replacing a vendor tool by something you build in-house is probably not worth it in the mental bandwidth that you've lost." 把 technical bandwidth 用在 core competencies，而不是重造 vendor tools。

### 不断更新 priors
Aparna Chennapragada: "The models couldn't do some things one year ago. My impression of it from trying it a few months ago - that prior needs to be updated. The baby just grew up to be a 15-year-old in a month." 每隔几个月重新测试关于 technology 能力的假设。

### 押注 abstraction layers
Asha Sharma: "You really need to bet on a platform or some app server type layer that allows you to swap things in and out and not really be beholden to any one technology." 随着 AI stack 演进，投资 modularity。

### AI guardrails 不可靠
Sander Schulhoff: "AI guardrails do not work. If someone is determined enough to trick GPT-5, they're going to deal with that guardrail. When these guardrail providers say 'We catch everything,' that's a complete lie." 对 AI security vendor claims 保持怀疑。

### 亲自使用 tools
Dhanji R. Prasanna: "I would say really try and use these tools yourself. We learn a lot about how our own workflow can change." 用新 tools 解决一个具体个人问题，理解其真正 strengths。

### Context 驱动 AI value
Jeanne Grosser: "Because this whole space is so nascent, often your own esoteric context, your content, your workflow is really key to unlocking the power of the agent." 对 AI agents 来说，内部构建常常胜过购买。

## 帮助用户的问题

- "你想用这项 technology 解决哪个具体问题？"
- "这项 technology 对 production 足够稳定，还是仍然 experimental？"
- "Build 的 mental bandwidth cost 与维护 vendor relationship 的成本分别是什么？"
- "你上一次测试这项 technology 能力假设是什么时候？"
- "如果更好的东西出现，你如何替换掉它？"
- "你是否亲自用这个 tool 解决过真实问题？"

## 需要提醒的常见错误

- **Tool bias** - 因为以前用过某工具而选择它，而不是因为它解决问题
- **Binary build vs buy thinking** - 错过购买 90%、构建战略性 10% 的机会
- **Outdated priors** - 基于六个月前 technology 做不到什么来做今天的决策
- **Vendor lock-in** - 没有为未来灵活性建立 abstraction layer，就押注特定 tools
- **相信 security marketing** - 相信 AI guardrail vendors 所谓 'catch everything' 的说法
